## For DEVIATIONS.md

- Under "Crashes in the original": **`CSpeaker::SpeakerThink` with a preset outside 1-12 plays
  nothing.** The original reads whatever its sound-name register held (no default case);
  halflife-updated's `""` default stays (`dlls/sound.cpp`).
- Under "Crashes in the original": **`CBullsquid::HandleAnimEvent`'s spit tests for an enemy**
  (`dlls/bullsquid.cpp`, VERIFY), halflife-updated's test. Already in the w2-monsters dossier.
- Under "Save data": **save/restore keeps halflife-updated's buffer code**: 1-byte booleans,
  `FIELD_INT64`, pointer-size function fields, the empty token table test and its `\n`-ended
  messages (`dlls/util.cpp`). Singleplayer only; save files aren't compatible anyway.
- Proposed, if Steven keeps it (see unclear below): **env_sound's room type reaches the client
  from `CBasePlayer::UpdateClientData`**, resent on every spawn and full update and reset to 0 on
  a new map. The original sends `SVC_ROOMTYPE` once, when an env_sound takes over, and never
  resets it.

## For ORIGINAL_BUGS.md

- Crashes: `sound.cpp CSpeaker::SpeakerThink | preset outside 1-12: uses an uninitialized name pointer | guarded`.
- Logic: `sound.cpp CAmbientGeneric | plays on CHAN_STATIC via EMIT_SOUND_DYN, so a loop started at map load (Precache) may reach no client | kept (VERIFY)`.
- Logic: `monsters.cpp CBaseMonster::OpenDoorAndWait | no IsLockedByMaster test: monsters open master-locked doors | kept`.
- Logic: `monsters.cpp CBaseMonster::ReportAIState | state names lack PlayDead: PLAYDEAD prints "Dead", DEAD prints none | kept`.

## Unclear (Steven decides)

- **`CEnvSound::Think`** (0x214760). Inside the function the two versions pick the same winner
  and the client ends up with the same room type; halflife-updated only defers the send to
  `UpdateClientData` and clears `m_SndLast` instead of the room type. What a player can hear
  differently lives in `player.cpp` (not mine): `m_ClientSndRoomtype = -1` on spawn,
  `ForceClientDllUpdate` and restore resends the room type, and `m_SndRoomtype` starts at 0 each
  map, so a DSP effect no longer carries over into the next map or survives a reconnect the way
  it would on the original. Reverting means putting the `SVC_ROOMTYPE` write back here and
  removing the player.cpp send. Kept as is.

## Odd

- **The drift list can't see every RC change.** It lists functions whose body in our tree
  differs from SDK 2.1. A function ours has exactly as SDK 2.1 while the original differs isn't
  in it. `CAmbientGeneric::Precache` and `::ToggleUse` are two: they carry the same CHAN_STATIC
  change as `RampThink` (one of my rows), so I changed all three (fixing only RampThink would ramp
  a sound the entity never started). The islave and OpenDoorAndWait finds show the original drops
  SDK code without leaving a string or call skim.py notices; a pass of `r4-strmiss.py` /
  `r4-callmiss.py` over every stock function, not only the drift rows, would find the rest.
- **The CHAN_STATIC change is a big one for play.** If the engine sends an entity sound made
  before any client connects to nobody (an ambient sound goes into the signon buffer), every
  ambient_generic loop that starts on spawn was silent on RC 1.9 until triggered, and is silent
  again now. Not checked in an engine; the spot is marked VERIFY in `CAmbientGeneric::Precache`.
- `CSave::WriteFunction`'s message differs from every SDK in the archive (2.0, 2.1, 2.2), so it
  is RC's own wording. Singleplayer only; restored anyway since it costs nothing.
- `CISlave::Precache` in the original has no `debris/zap1.wav`; the string isn't in the binary
  at all.
