read three ways: SDK 2.1 (SDK 2.1's `src` from the hlsdk-archive `v2_1-full` release), ours, and the

## For DEVIATIONS.md

- Cvars: add `sv_pushable_fixed_tick_fudge` to the cvars that have no effect: `CPushable::Move`
  (`dlls/func_break.cpp`) is SDK 2.1's again and nothing else reads it.
- Crashes in the original: **`func_breakable` material 9 (`matNone`) precaches and sounds as wood**
  (`dlls/func_break.cpp` `Precache`, `DamageSound`). KeyValue lets 9 through and the original then
  precaches an uninitialized model name; halflife-updated's `default:` is kept as the guard.
- Crashes in the original: **a `func_plat`'s inside trigger removes itself when its platform is
  gone** (`dlls/plats.cpp` `CPlatTrigger`, halflife-updated's EHANDLE); the original reads the freed
  platform.
- Crashes in the original: **`CSoundEnt::ISoundsInList` counts 0 for an unknown list type**, and
  **`trigger_counter` tests for a null activator** (`dlls/soundent.cpp`, `dlls/triggers.cpp`
  `CounterUse`); both halflife-updated's, kept as guards.
- Save data: `trigger_camera` sets and clears halflife-updated's `m_hViewEntity` (the view restore on
  load), kept; it shows only across a save.

## Odd

- **`sv_chglevel` isn't dead.** `docs/SERVER.md` says it is "registered, read by nothing (the
  original too)", but the original's `CChangeLevel::ChangeLevelNow` reads it by name: in deathmatch
  a player touching or firing a `trigger_changelevel` (with `sv_noexit` off) takes the server to
  that map when it is 1 and the map is valid. Now reconstructed; SERVER.md's line (not my file)
  should read something like `sv_chglevel 0 in deathmatch, 1 lets a player change the map through a
  trigger_changelevel (sv_noexit 0)`.
- Several functions carrying `// orig 0x...` still had halflife-updated's code in them:
  `CBreakable::Die` (all three play changes), `CBaseTrigger::HurtTouch` (the dead-player heal test
  and the missing driven-monster test on CLIENTONLYFIRE). An earlier package tagged them for RC's
  part and left the rest as found.
- `PlayCDTrack` (`dlls/triggers.cpp`, no row: the original inlines it into the two Play functions)
  still uses `UTIL_GetLocalPlayer`; the original sends to client 1's edict. With an empty slot 1
  ours sends nothing, the original sends to an unconnected client, which the engine drops, so I left
  it. mod-rc2 also reverted a "cd stop" change in its `CTargetCDAudio::Play`; ours has no row for
  Play, so it matches SDK 2.1.
- `CBreakable::TakeDamage`'s DAMAGE_NO test (RC's or Valve's post-2.1 code, not in SDK 2.1 or 2.0)
  and halflife-updated's SOLID_NOT test in `Die` cover the same double break from two sides; with
  the first back in, TakeDamage can't break a killed breakable again, while two uses before the
  remove still can, as in the original.
- `CTriggerCamera::Use` now takes `CBaseEntity::Instance(INDEXENT(1))` for a non-player activator,
  as the original does, with the original's own validity checks in front of the toggle;
  `UTIL_GetLocalPlayer` is gone from it.
