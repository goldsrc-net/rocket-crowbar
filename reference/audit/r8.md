# r8: stock functions ours has exactly as SDK 2.1

`sdk-drift.tsv` only lists functions whose body in our tree differs from SDK 2.1's. A function ours
has exactly as SDK 2.1 while the original changed it never showed up there (r4's
`CAmbientGeneric::Precache` / `::ToggleUse`, and `CItemBattery::MyTouch` before that). r8 screens
all of those against the original's decompile.

Classes as BRIEF.md. Every row here is `equal` (ours folds to SDK 2.1's body), so the only possible
classes are `missed` (RC changed it; reconstructed) and false hits.

## How I screened

Helpers are in `~/stignored/rc19-tools/audit/`:

- `r8-equal.py`, a copy of `scripts/stock_drift.py` that prints `equal` and `differs` rows as well
  as `not in base`. It also blanks comments and `#if 0` blocks before looking for a body, because
  `body()` matches a commented-out copy. `combat.cpp` keeps an old `CBaseMonster::TraceAttack`
  inside `/* */` above the real one, and both sides were matching that copy. The blanking changed
  no row's class in this tree, but the same bug is still in `scripts/stock_drift.py`.
  Output: `r8-equal.tsv`.
- `r8-screen.py <eq.tsv> [bodiesdir]` compares SDK 2.1's body (comments, `#if 0` and `ASSERT`s
  dropped) with the decompile, following Ghidra's split `FUN_` pieces from `_free.c` (SPLIT). It
  checks:
  - string literals one side has and the other lacks. Strings the decompile only gives as
    `DAT_`/`FUN_`/hex addresses are resolved in the `.so`'s .rodata/.data.
  - names SDK 2.1 calls that the decompile never names. Header and in-class inlines and macros
    are excluded, and a row counts only when it has more missing names than untyped vtable calls.
  - mangled or vtbl names the decompile calls that SDK 2.1 doesn't.
  - float constants the original has that SDK 2.1's body (with macros expanded, plus x, -x, 1/x
    and pairwise products, sums and differences) lacks, and the reverse. Floats come from DAT
    loads and float bit patterns.
  - `member = constant` stores that differ.
  - a size ratio: decompile lines per SDK statement.

  Output: `r8-screen.out`.
- `r8-instr.py` says whether each string is anywhere in the `.so`. `r8-strref.py <rva>` lists the
  strings a function really references through its PIC base (`%ebx`), for decompiles that lost
  their arguments. `r8-ctx.py` prints matching lines of both bodies.

## Odd

- **`scripts/stock_drift.py` can match a commented-out function.** `body()` runs on raw text, so a
  `/* ... */` copy above the real function (combat.cpp's old `CBaseMonster::TraceAttack`) is the
  one compared, on both sides. In this tree it changes no row, but a function whose real body
  drifted would be missed. `r8-equal.py` has the fix (blank comments and `#if 0` keeping offsets)
  if Steven wants it in the script.
- **Blind spot:** integer constants are only screened through `member = constant` stores. A changed
  integer argument (damage, a channel, a flag passed to a call) or a changed comparison against an
  integer wouldn't show unless it also changed a string, a call or a float. CTentacle's
  `m_iTapSound` came up only because it shares a constructor with a float.
- `CTalkMonster::AlertFriends` completes the sv_loyalnpcs work: Barney's and the scientists'
  TakeDamage already test it (dlls/barney.cpp, dlls/scientist.cpp). Before this fix, killing one
  of them still turned the rest against the player.
- `CBaseMonster::DamageForce` is used by every monster's and player's TakeDamage knockback, so the
  1500 cap shows in multiplayer: a hit big enough to reach the cap (a rocket, a satchel) pushes a
  player up to 1.5 times as far.
