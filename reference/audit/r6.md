## For DEVIATIONS.md

- Cvars: `mp_fragsleft` and `mp_timeleft` are not just registered, `CHalfLifeMultiplay::Think`
  keeps them updated (halflife-updated's code). The original's Think writes neither.
- Crashes in the original: `CLightning::StrikeThink` (`dlls/effects.cpp`): an env_beam with the
  ring flag and a point entity at one end returns with its temp-entity message still open, so the
  next message start is an engine error. Ours checks before `MESSAGE_BEGIN` (halflife-updated's order).
- Crashes in the original: the nihilanth's target names are built in 64- and 36-byte buffers from
  64-byte keyvalues plus a number (`NextActivity`, `HandleAnimEvent`); ours uses 128 bytes.
- Crashes in the original: the hornet's `DieTouch` passes a null attacker when its owner is gone, and
  the osprey's `FlyThink` reads a null goal entity (both already marked VERIFY).
- Unclear, kept: `CFuncTank::AdjustAnglesForBarrel` skips the barrel correction when the target is
  nearer than the barrel offset. The original takes the square root of a negative there and aims
  with NaN angles.

## Odd

- SDK 2.1's `CHalfLifeMultiplay` constructor execs `servercfgfile`/`lservercfgfile` and its Think
  writes `mp_fragsleft`/`mp_timeleft`. The original does neither, and DEVIATIONS says those cvars
  post-date RC's SDK. Either RC removed them or RC's base is older than this 2.1 archive; worth
  knowing when another row "matches SDK 2.1" by the archive.
- `CBasePlayer::EquipWeapon` (`dlls/player.cpp`, halflife-updated's) has no caller now that
  `StopControl` deploys as the original. Left in place; player.cpp isn't mine.
- `CHornet::DieTouch`'s guard also skips the hit sound, more than the smallest check. Only reachable
  with no owner (a level transition), so it changes nothing in multiplayer; left as it was.
- `COsprey::FlyThink`'s guard block is mis-indented (an earlier package's); left as it was.
- `CShotgun::Reload`'s comment "relative in halflife-updated (the player decrements it)" describes
  the client build; the server is built without CLIENT_WEAPONS, so `m_flNextAttack` is absolute
  there, as the original. Left as it was.
- `CShotgun::SecondaryAttack`'s decompile is a stub that jumps to a `FUN_` fragment; it was
  reconstructed earlier and isn't halflife-updated drift, so it wasn't re-read against the
  disassembly here.
