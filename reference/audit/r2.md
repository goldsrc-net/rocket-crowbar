# Audit r2: halflife-updated's changes in RC 1.9's stock-named functions

Files: `reference/audit/r2.files`. For each row of `sdk-drift.tsv` in those files I read SDK 2.1's body
(SDK 2.1's `src` from the hlsdk-archive `v2_1-full` release), ours and the original's decompile
(`recovered/decomp/<Class>.c`), side by side (`~/stignored/rc19-tools/audit/show3.py <worktree> r2`).
The disassembly settled the start of `CSatchelCharge::SatchelThink`, which Ghidra split into a
fragment. String operands (`DAT_...`) were resolved from `reference/rc_i386.so`.

Counts: done 56, style 36, engine 6, guard 3, sp 2, play 0, missed 0, unclear 0.

The weapon files (egon, handgrenade, rpg, satchel) and RC's changes in barney, headcrab, houndeye,
ichthyosaur and world were reconstructed by earlier packages. Each of them matches the original,
halflife-updated leftovers included. The rest are stock: the original does what SDK 2.1 does, and
halflife-updated's changes there don't show in play.

The only edits are two stale comments: `CEgon::AddToPlayer` and `CRpg::AddToPlayer` said
`AddPlayerItem` sends `WeapPickup`, which it no longer does in this tree. The rpg one also had a
`VERIFY` that this settles: the original's base `AddToPlayer` always succeeds, so the message always
goes out, as ours sends it.

## For DEVIATIONS.md

- **A second `worldspawn` removes itself** (`CWorld::Precache`, kept from halflife-updated). In the
  original, any extra worldspawn (a map with two, or one a `.lec` creates) runs the whole map setup
  again: new game rules, rc.ini reload, votes reset, every spawner created a second time.
- **`game_score` and `game_player_equip` ignore a missing activator** (halflife-updated's null
  checks). The original calls `IsPlayer()` through the null pointer and crashes.
- **Node graphs are read and written through the engine filesystem; on amd64 the file is
  `maps/graphs/<map>.nod64`** (halflife-updated, because CGraph and CLink hold pointers). i386
  keeps `.nod`, version 16, as the original.

## For ORIGINAL_BUGS.md

- nodes.cpp `CGraph::ComputeStaticRoutingTables`: scalar `delete` on four `new[]` arrays (Valve's
  SDK). Ours: changed (`delete[]`, from halflife-updated), like the CVEC entry.
- maprules.cpp `CGameScore::Use`, `CGamePlayerEquip::EquipPlayer`: crash on a NULL activator.
  Ours: guarded (halflife-updated's checks).

The egon shake centre and the rpg Reload `iResult` are already in their wave-2 dossiers.

## Odd

- `CSatchel::AddToPlayer` goes through `CBasePlayerWeapon::AddToPlayer`, so it also looks up the
  ammo index the way the original's satchel didn't. The index comes out the same as the one the
  original's first ammo pickup stores, so nothing differs in play.
- Every `nodes.cpp` function's strings and logic match SDK 2.1: RC didn't touch the node graph.
